# nlbwmon-aggregator: обзор проекта

[English](../en/OVERVIEW.md) | **Русский**

Проект содержит **два разных пути обработки** событий conntrack. Их нельзя путать при установке.

## 1. Агрегатор (legacy)

`aggregator.py` принимает текстовые DESTROY-события conntrack и JSONL-события `nlbwmon-flow-v1`, группирует данные и отправляет агрегированные документы в Fluent Bit. Для JSONL учитывает DESTROY; NEW не прибавляется повторно к счётчикам.

## 2. Коллектор жизненного цикла

`flow_collector.py` принимает события NEW/DESTROY, сохраняет их в SQLite (WAL) и отправляет обновления документов непосредственно в OpenSearch. В ветке подготовки используется пакетная отправка через Bulk API; возможна асинхронная обработка PTR. Fluent Bit для этого пути не нужен.

Эти сервисы различаются назначением и конфигурацией. Не направляйте поток на произвольный порт без проверки схемы приёмника.

## Ограничения и безопасность

- Экспортёр на роутере отправляет события по TCP без прикладного подтверждения: SQLite на приёмнике не гарантирует восстановление событий, потерянных до записи.
- Данные содержат IP-адреса, порты и сведения о соединениях. Ограничьте доступ к приёмнику, OpenSearch и журналам.
- Для OpenSearch храните учётные данные вне Git и проверяйте TLS.
- Перед обновлением сохраняйте рабочую конфигурацию и проверяйте восстановление.

> Статус: подготовка beta-релиза. Документацию по установке необходимо сверить с итоговым релизным кодом, прежде чем считать её инструкцией для пользователей.
